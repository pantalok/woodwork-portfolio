# Woodworking portfolio

A static portfolio site built from a folder of photos and videos. Plain HTML, CSS and
JavaScript in `dist/`, generated by a few Python scripts. No framework, no build step
needed to view it.

## Layout

```
media/original/   your raw photos and videos (git-ignored, back these up yourself)
media/derived/    private cache of resized images and web videos for EVERY file (git-ignored)
data/             your curation: projects.yaml, unassigned.yaml, site.yaml (+ generated inventory/derivatives JSON)
site/static/      CSS, JS, fonts
scripts/          the pipeline
dist/             the published site (tracked in git; GitHub Pages serves it)
```

Only files that belong to a published project are copied into `dist/media`.
Hidden or unassigned files stay in `media/derived` on your machine.

## One-time setup

```sh
brew install ffmpeg                  # macOS; needed for video
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## Everyday workflow

1. **Add photos or videos** to `media/original/` (any names, any folder structure).
2. **Index and resize them**:
   ```sh
   .venv/bin/python scripts/ingest.py      # reads EXIF, writes data/inventory.json
   .venv/bin/python scripts/process.py     # resizes, strips metadata, encodes video (cached)
   ```
3. **Curate in the editor**:
   ```sh
   .venv/bin/python scripts/curate.py      # opens http://127.0.0.1:8765/
   ```
   New files appear at the bottom under "Not in any project". Drag them into a project
   or create one. Fill in titles, details and captions. Set your name and tagline under
   Site settings. Press **Save and rebuild**.
4. **Preview**:
   ```sh
   cd dist && python3 -m http.server 8000  # then open http://localhost:8000/
   ```
   Opening `dist/index.html` directly also works.
5. **Check and publish**:
   ```sh
   .venv/bin/python scripts/check.py       # links, dimensions, orphans, page weight
   git add -A && git commit -m "Update site" && git push
   ```
   The GitHub Actions workflow publishes `dist/` to GitHub Pages on every push to `main`.

You can also edit `data/projects.yaml` and `data/site.yaml` by hand and run
`scripts/build_site.py`. Comments in the YAML show the original filename next to each id.

## Scripts

| Script | What it does |
|---|---|
| `scripts/ingest.py` | Walks `media/original/`, hashes files, extracts dates and dimensions, prints a summary. |
| `scripts/process.py` | Makes 640px and 1800px WebP+JPEG versions, video posters and 1080p MP4s into `media/derived/`. Skips work that is already done; `--force` redoes everything. |
| `scripts/propose_clusters.py` | First-pass grouping into projects. Only for a fresh start; refuses to overwrite your `projects.yaml` without `--force`. |
| `scripts/preview_clusters.py` | Scratch HTML page of the current grouping. |
| `scripts/curate.py` | The local editor. |
| `scripts/build_site.py` | Generates `dist/` from the YAML and copies the used media in. |
| `scripts/check.py` | Validates `dist/` before publishing. |

## Deploying

**GitHub Pages (set up):** push to `main`. The workflow in `.github/workflows/pages.yml`
uploads `dist/` and deploys it. The site URL is shown in the repo's Settings → Pages.

**Netlify:** drag the `dist/` folder onto app.netlify.com, or connect the repo;
`netlify.toml` already points at `dist/` with no build command.

All links in the site are relative, so it works at a sub-path such as
`https://<user>.github.io/<repo>/` as well as on a custom domain.

## Privacy notes

- Derivatives have all EXIF, GPS and colour-profile metadata stripped. Filenames in
  `dist/media` are content hashes, not your original names.
- `data/*.yaml` and `data/inventory.json` do contain your original filenames and capture
  dates as comments and fields. They are in the public repo. Rename files in
  `media/original/` before ingesting if a filename says something you would rather not publish.
- Files you hide in the editor are never copied to `dist/`.
